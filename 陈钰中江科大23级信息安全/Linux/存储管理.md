# 硬盘设备命名

 ## 传统 IDE/PATA 硬盘

- **命名格式**: `hd[a-z]`
  - **分区命名**:
    - 主分区: `hda1`-`hda3`
    - 扩展分区: `hda4`
    - 逻辑分区: `hda5`开始

- **示例**:
  - `/dev/hda1` (第一个主分区)
  - `/dev/hda4` (扩展分区)
  - `/dev/hda5` (第一个逻辑分区)
- **特点**:
  - 逐渐淘汰，现代系统更多使用 SATA/SCSI 命名规则

## SATA/SCSI/SAS/USB 硬盘

- **命名格式**: `sd[a-z]`

  - **分区命名**:
    - 主分区: `sda1`-`sda3`
    - 扩展分区: `sda4`
    - 逻辑分区: `sda5`开始
      - 完全包含在扩展分区内
      - 数量理论上无限制（实际受系统约束）
      - 编号从 **5开始**（1-4保留给主分区）
      - 通过扩展分区内的 **二级分区表** 管理

- **示例**:

  - `/dev/sdb1` (第二块硬盘的第一个主分区)
  - `/dev/sdb5` (第二块硬盘的第一个逻辑分区)



## NVMe SSD

- **命名格式**: `nvme[0-9]n[0-9]`
  - **分区命名**:
    - 主分区: `nvme0n1p1`-`nvme0n1p3`
    - 扩展分区: `nvme0n1p4`
    - 逻辑分区: `nvme0n1p5`开始
- **示例**:
  - `/dev/nvme0n1p1` (第一个NVMe设备的第一个主分区)
  - `/dev/nvme0n1p5` (第一个NVMe设备的第一个逻辑分区)

## 虚拟设备

- **命名格式**: `vd[a-z]`
  - **分区命名**:
    - 主分区: `vda1`-`vda3`
    - 扩展分区: `vda4`
    - 逻辑分区: `vda5`开始
- **示例**:
  - `/dev/vdb2` (第二个虚拟硬盘的第二个主分区)

## 其他物理设备命名

| 硬件设备 |     文件名称       |
| ------ | ------------------ |
| 软驱   | /dev/fd[0-1]       |
| 打印机 | /dev/lp[0-15]      |
| 光驱   | /dev/cdrom         |
| 鼠标   | /dev/mouse         |
| 磁带机 | /dev/st0或/dev/ht0 |

# 分区表

分区表是存储在磁盘起始扇区中的数据结构，用于记录磁盘的分区布局（如分区数量、大小、类型等）。它相当于磁盘的“目录”，告诉操作系统如何访问和管理不同分区。

## 分区表作用

- **定义分区边界**：记录每个分区的起始和结束位置（柱面/扇区）。
- **标识分区类型**：如 NTFS、FAT32、Linux swap 等。
- **支持多系统启动**：允许不同操作系统共存于同一磁盘的不同分区。
- **保护数据隔离**：防止一个分区的错误影响其他分区。

## 分区表类型

### MBR（Master Boot Record）

- **分区命名**

  MBR 的分区命名遵循 **主分区 + 扩展分区 + 逻辑分区** 的规则

  - **主分区**：编号 **1-4**（如 `/dev/sda1`、`/dev/sda2`）
  - **扩展分区**：占用 **1 个主分区号**（通常是 `4`，如 `/dev/sda4`）
  - **逻辑分区**：从 **5 开始编号**（如 `/dev/sda5`、`/dev/sda6`）

    ~~~tex
    sda1 (主分区，20GB)
    sda2 (主分区，30GB)
    sda3 (主分区，50GB)
    sda4 (扩展分区，100GB)
      ├─ sda5 (逻辑分区，30GB)
      ├─ sda6 (逻辑分区，40GB)
      └─ sda7 (逻辑分区，30GB)
    ~~~

- **特点**：
  - 传统分区表，兼容性极强（支持 BIOS 启动）
  - 最大支持 **2TB** 磁盘，最多 **4个分区**
    - 有两种情况
      - 四个主分区
      - 三个主分区 + 一个扩展分区
    - 扩展分区：内部可以划分**多个逻辑分区**，但是所有逻辑分区在分区表中都算在一个分区内
  - 分区信息存储在磁盘的第一个扇区（512字节）

- **结构**：
  - **引导代码**（前446字节）：用于启动操作系统
  - **分区表**（64字节）：记录4个分区的信息
  - **结束标志**（2字节：`0x55AA`）

### GPT（GUID Partition Table）

- **分区命名**

  GPT **没有主/扩展/逻辑分区的概念**，所有分区都是 **主分区**，编号从 **1 开始连续递增**：

  - **SATA/SCSI/SAS/USB 硬盘**：`/dev/sd[a-z][分区号]`（如 `/dev/sda1`、`/dev/sda2`）
  - **NVMe SSD**：`/dev/nvme[控制器号]n[命名空间号]p[分区号]`（如 `/dev/nvme0n1p1`、`/dev/nvme0n1p2`）
  - **虚拟硬盘**：`/dev/vd[a-z][分区号]`（如 `/dev/vda1`、`/dev/vda2`）

  ```tex
  /dev/sda1  (EFI 系统分区)
  /dev/sda2  (根分区 /)
  /dev/sda3  (/home 分区)
  /dev/sda4  (交换分区 swap)
  ```

- **特点**：

  - 现代分区表，支持 **UEFI 启动**。
  - 最大支持 **18EB（艾字节）** 磁盘，理论上无限分区数量（实际限制由操作系统决定）。
  - 具有冗余备份，更安全。

- **结构**：
  - **保护性MBR**（兼容旧系统）。
  - **GPT头**：记录分区表位置和校验信息。
  - **分区条目数组**：每个条目128字节，可包含多个分区。
  - **备份GPT头**：防止主分区表损坏。

### 类型对比

| **特性**         | **MBR**                          | **GPT**                          |
| :--------------- | :------------------------------- | :------------------------------- |
| **最大磁盘容量** | 2TB                              | 18EB（1EB=1024PB）               |
| **最大分区数量** | 4个主分区（或扩展分区+逻辑分区） | 理论上无限（Windows限制为128个） |
| **启动方式**     | 仅支持 BIOS                      | 支持 UEFI 和 BIOS（需兼容模式）  |
| **安全性**       | 无校验，易损坏                   | CRC校验，备份分区表              |
| **兼容性**       | 所有操作系统                     | 较新系统（Windows Vista+/Linux） |

# 文件系统

当我们在硬盘上完成分区后，还需要为这些分区建立一套"管理规则"——这就是文件系统。简单来说，文件系统决定了数据在磁盘上的存储和读取方式，就像图书馆需要一套图书分类管理系统一样。

## 文件系统的核心作用

文件系统主要解决三个关键问题：

1. **存储规范**：数据应该按照什么格式存放
2. **读取规则**：如何快速准确地找到所需数据
3. **空间管理**：如何高效利用磁盘空间

## Linux文件系统的主要类型

虽然Linux支持数十种文件系统，但主要分为两大类：

### 日志式文件系统

- **特点**：记录操作日志，意外断电时能快速恢复
- **代表**：ext4、XFS、Btrfs
- **适用场景**：需要高可靠性的场景

## 主流 Linux 文件系统

### Ext3 (Third Extended File System)

**特点：**

- 日志式文件系统，提供数据一致性保障
- 系统异常宕机时可避免文件系统资料丢失
- 自动修复数据不一致与错误

**局限性：**

- 硬盘容量大时修复时间较长
- 不能100%保证资料不丢失
- 记录整个磁盘的每个写入动作细节

### Ext4 (Fourth Extended File System)

**改进点：**

- RHEL 6默认文件系统
- 支持高达1EB(约10亿GB)的存储容量
- 支持无限数量的子目录
- 批量分配block块，提高读写效率
- 引入"extents"概念，减少文件碎片

**技术参数：**

- 最大文件大小：16TB
- 最大文件系统大小：1EB

### XFS (X File System)

**优势：**

- RHEL 7默认文件系统
- 高性能日志文件系统
- 宕机后能快速恢复
- 日志功能性能开销低
- 支持高达18EB的存储容量

**特点：**

- 特别适合大文件处理
- 延迟分配策略减少碎片
- 并行I/O操作

### Btrfs (B-Tree File System)

- 先进的文件系统，支持许多现代特性
- 功能包括：
  - 写时复制(CoW)
  - 快照
  - 内置RAID支持
  - 子卷
  - 透明压缩

### ZFS

- 最初由Sun Microsystems开发
- 特性：
  - 存储池概念
  - 数据完整性校验
  - 自动修复
  - 极高的可扩展性

### Swap（交换分区）

- 特殊文件系统用于虚拟内存
- 当物理内存不足时使用
- 在生产环境中，交换分区的大小一般为真实物理内存的1.5～2倍

## 文件系统核心概念

### 格式化过程

- **日志式文件系统**：先清除inode表
- **索引式文件系统**：先清除第一个索引，标记空间可用

### 关键数据结构

#### Superblock (超级块)

- 记录文件系统整体信息
- 包含：
  - inode/block的总量、使用量、剩余量
  - 文件系统格式及相关信息

#### Inode (索引节点)

- 记录文件属性，每个文件占用一个inode
- 默认大小：128字节
- 记录文件数据所在的block号码
- 包含信息：
  - 访问权限(r/w/x)
  - 所有者与所属组
  - 文件大小
  - 时间戳(ctime/atime/mtime)
  - 特殊权限(SUID/SGID/SBIT)
  - 真实数据地址指针
- 当记录满时会新建inode扩展

#### Block (数据块)

- 实际存储文件数据的单元
- 大小通常为1KB、2KB或4KB

## 虚拟文件系统(VFS)

**作用：**

- 为用户程序提供统一接口
- 屏蔽不同文件系统的底层差异

**优势：**

- 用户无需关心底层硬盘结构
- 支持多种文件系统共存
- 提供一致的文件操作API
